# IonoAutoML

Рабочий исследовательский проект для сбора, подготовки, нормализации и анализа ионосферных данных. Основная задача проекта - подготовить данные по станциям GIRO, добавить геофизические индексы, построить признаки и обучить модели для прогноза параметра `foF2`.

В репозитории хранятся код, конфигурации, ноутбуки и небольшие служебные файлы. Большие наборы данных и полные результаты экспериментов хранятся отдельно от кода.

## Что делает проект

Проект собирает и объединяет несколько групп данных:

- GIRO DIDBase/FastChar - ионосферные параметры по станциям.
- GFZ Kp API - геомагнитные и солнечные индексы `Kp`, `ap`, `Ap`, `Fobs`, `Fadj`.
- NASA OMNIWeb - параметры межпланетного магнитного поля и солнечного ветра.
- NOAA/SWPC - дополнительный источник live-продуктов, не основной источник исторических данных.

После сбора данные очищаются, приводятся к регулярной временной сетке, разбиваются по станциям и превращаются в обучающие таблицы. Затем запускаются ML-эксперименты, сохраняются метрики, прогнозы и сводные таблицы.

## Что уже сделано

- Настроен сбор данных GIRO, GFZ и OMNI за 2024-2025 годы.
- Добавлена защита от ошибки GIRO: один запрос не пересекает границу календарного года.
- Подготовлена очистка таблиц и нормализация временных рядов.
- Сформирован набор станций для первых экспериментов.
- Построен feature dataset для ML-моделей.
- Запущены модели для прогноза `foF2`; быстрый основной прогон выполнен для горизонта 24 часа, а в feature dataset также подготовлены горизонты 15 минут, 1 час, 3 часа и 6 часов.
- Получены метрики качества по станциям и моделям.
- Подготовлен анализ качества моделей по широтным зонам.
- Подготовлен ноутбук для анализа стационарности временных ходов `foF2`.

## Структура проекта

### Основные скрипты

- `collect_hf_data.py` - собирает данные из GIRO, GFZ, OMNI и NOAA.
- `clean_collected_data.py` - очищает собранные таблицы и формирует промежуточный набор данных.
- `normalize_time_grid.py` - приводит ряды к единой временной сетке, сохраняет таблицы по станциям.
- `build_features.py` - строит признаки для обучения: текущие значения, лаги, разности и target-колонки.
- `run_ml_baselines.py` - обучает модели, считает метрики, сохраняет прогнозы и отчеты.
- `run_station_batch.py` - запускает обучение по списку станций.
- `watch_run_progress.py` - показывает прогресс длинного ML-запуска.

### Конфигурации

- `config.toml` - базовые настройки сбора данных.
- `configs/time_normalization.json` - правила нормализации временной сетки.
- `configs/time_series_filtering.json` - настройки фильтрации временных рядов перед построением нового feature dataset.
- `configs/station_selection.json` - правила отбора станций.
- `configs/feature_engineering.json` - настройки построения признаков.
- `configs/stations_metadata.csv` и `configs/stations_metadata.json` - координаты и метаданные станций.
- `configs/station_sets/exploration_v0.1.json` - набор 41 станции для первых экспериментов.
- `configs/station_sets/fof2_fast_ml_24h_all_available.txt` - список станций для быстрого эксперимента `foF2` на 24 часа.
- `configs/experiments/baseline_v0.1.json` - базовый ML-эксперимент.
- `configs/experiments/fof2_fast_ml_24h.json` - быстрый эксперимент для прогноза `foF2` на 24 часа.
- `configs/experiments/fof2_fast_ml_24h_automl_shap.json` - расширенный эксперимент с AutoML/SHAP.
- `configs/experiments/fof2_fast_ml_24h_filtered.json` - быстрый эксперимент на данных после фильтрации.
- `configs/experiments/fof2_fast_ml_24h_filtered_automl_shap.json` - эксперимент на данных после фильтрации с AutoML/SHAP.

### Ноутбуки

- `notebooks/ml_results_review.ipynb` - просмотр и сводный анализ результатов ML.
- `notebooks/ml_results_review.executed.ipynb` - выполненная копия ноутбука с сохраненными выводами.
- `notebooks/quick_quality_plots_ascii.ipynb` - быстрые графики покрытия и качества данных.
- `notebooks/stationarity_latitude_analysis.ipynb` - анализ стационарности временных ходов `foF2` по широтным зонам.

### Локальные данные и результаты

Эти папки используются в работе с данными и результатами:

- `data_2024_2025_giro/` - сырые данные GIRO.
- `data_2024_2025_indices/` - собранные геофизические индексы.
- `cleaned_2024_2025/` - очищенные таблицы.

- `features_2024_2025_exploration_v0_1_15min/` - обучающий dataset, который использовался для моделей.

### Состояние набора станций

В текущем скане покрытия за 2024-2025 годы найдено 120 GIRO-станций:

- 65 станций без строк измерений;
- 55 станций с данными.

Для 55 станций с данными при шаге `5min` получены мягкие классы качества:

- `good` - 18 станций с хорошим покрытием целевого параметра и небольшим количеством пропусков;
- `usable` - 23 станции, пригодные для исследовательских экспериментов, но с предупреждениями по покрытию или пропускам;
- `weak` - 13 станций со слабым покрытием, которые лучше не брать в основной набор, но можно использовать для отдельного анализа устойчивости;
- `exclude` - 1 станция с почти отсутствующим полезным целевым рядом.

Для первых исследовательских экспериментов выбран набор `good + usable`, всего 41 станция. Этот набор зафиксирован в `configs/station_sets/exploration_v0.1.json`.

Координаты станций хранятся в `configs/stations_metadata.csv` и `configs/stations_metadata.json`. Для всех 41 выбранных станций координаты найдены.

Географическое распределение выбранных 41 станций:

- южные высокие широты - 1 станция;
- южные средние широты - 4 станции;
- низкие широты - 12 станций;
- северные средние широты - 21 станция;
- северные высокие широты - 3 станции.

Выборка пригодна для первого эксперимента, но имеет перекос в северные средние широты.

## Быстрый старт

Перейти в папку проекта:

```powershell
cd path\to\IonoAutoML
```

Запустить сбор данных по настройкам из `config.toml`:

```powershell
python .\collect_hf_data.py --config .\config.toml
```

По умолчанию рабочий период:

```text
2024-01-01T00:00:00Z <= time < 2026-01-01T00:00:00Z
```

Это означает весь 2024 год и весь 2025 год.

## Подготовка данных

Очистка собранных данных:

```powershell
python .\clean_collected_data.py `
  --input-dir data_2024_2025_indices `
  --giro-raw-dir data_2024_2025_giro\raw\giro `
  --output-dir cleaned_2024_2025 `
  --row-threshold 0.30 `
  --column-threshold 0.45
```

Нормализация по временной сетке:

```powershell
python .\normalize_time_grid.py `
  --time-config configs\time_normalization.json `
  --station-selection-config configs\station_selection.json `
  --giro-raw-dir data_2024_2025_giro\raw\giro `
  --processed-dir cleaned_2024_2025\processed `
  --output-dir normalized_2024_2025_exploration_v0_1_15min_by_station `
  --freq 15min `
  --min-cs 50 `
  --split-by-station
```

При нормализации GIRO-измерения агрегируются внутри временного окна. Значение `CS = -1` сохраняется как допустимое неизвестное качество, а не как плохая запись. Индексы GFZ и OMNI распространяются вперед только до своего `valid_until`, чтобы не использовать значения вне допустимого интервала.

Фильтрация временных рядов выполняется отдельным шагом и сохраняет результат в новую папку. Исходные нормализованные данные при этом не изменяются:

```powershell
python .\filter_time_series.py `
  --input-dir normalized_2024_2025_exploration_v0_1_15min_by_station `
  --config configs\time_series_filtering.json `
  --output-dir normalized_2024_2025_exploration_v0_1_15min_filtered_by_station
```

После фильтрации можно построить отдельный feature dataset:

```powershell
python .\build_features.py `
  --input-dir normalized_2024_2025_exploration_v0_1_15min_filtered_by_station `
  --config configs\feature_engineering.json `
  --output-dir features_2024_2025_exploration_v0_1_15min_filtered
```

## ML/AutoML запуск по станциям

Для основного быстрого эксперимента используется:

- целевой параметр: `foF2`;
- основной быстрый горизонт прогноза: `24h`;
- в полном наборе признаков дополнительно есть target-колонки для `15min`, `1h`, `3h` и `6h`;
- временная сетка: `15min`;
- период данных: 2024-2025 годы;
- оценка: walk-forward по 2025 году;
- окна обучения: `7`, `21`, `28` дней;
- модели: `LinearRegression`, `ElasticNet`, `RandomForest`, `XGBoost`, `CatBoost`.

Параметры обучения и прогноза:

- исходный feature dataset содержит 41 станцию;
- в файлах станций хранится примерно 141-155 feature-колонок, точное число зависит от доступных параметров станции;
- перед обучением для каждого train-окна признаки фильтруются по покрытию: используется только то, что заполнено минимум на 30%;
- в быстром эксперименте прогноз строится для `foF2` на 24 часа вперед, то есть target-колонка соответствует значению `foF2` через сутки после текущего момента;
- шаг временной сетки равен 15 минутам, поэтому сдвиг target составляет: 15 минут - 1 строка, 1 час - 4 строки, 3 часа - 12 строк, 6 часов - 24 строки, 24 часа - 96 строк;
- walk-forward идет по дням 2025 года: каждый split берет один тестовый день, затем окно сдвигается на следующий день;
- для каждого тестового дня отдельно проверяются train-окна 7, 21 и 28 дней;
- train-окно заканчивается перед тестовым днем, а последние точки train отсекаются на величину горизонта прогноза, чтобы target не попадал в будущий тестовый период;
- минимальный размер train для запуска модели - 48 строк, минимальный размер test - 2 строки;
- в быстром эксперименте `fof2_fast_ml_24h` AutoML/Optuna отключен, модели обучаются с фиксированными параметрами;
- в базовом эксперименте `baseline_v0.1` дополнительно есть горизонты `15min`, `1h`, `3h`, `6h`, `24h`, baseline-модели и Optuna-подбор для части моделей.

Запуск по списку станций:

```powershell
.\.venv\Scripts\python.exe .\run_station_batch.py `
  --config .\configs\experiments\fof2_fast_ml_24h.json `
  --station-file .\configs\station_sets\fof2_fast_ml_24h_all_available.txt
```

Проверить план запуска без обучения:

```powershell
.\.venv\Scripts\python.exe .\run_station_batch.py `
  --config .\configs\experiments\fof2_fast_ml_24h.json `
  --station-file .\configs\station_sets\fof2_fast_ml_24h_all_available.txt `
  --dry-run
```

Запустить одну станцию:

```powershell
.\.venv\Scripts\python.exe .\run_station_batch.py `
  --config .\configs\experiments\fof2_fast_ml_24h.json `
  --station TR169
```

Посмотреть прогресс длинного запуска:

```powershell
.\.venv\Scripts\python.exe .\watch_run_progress.py `
  --run-dir .\artifacts\fof2_fast_ml_24h
```

Для сравнения вариантов используются отдельные конфиги и отдельные папки результатов:

```powershell
# Без фильтрации, с AutoML/SHAP
.\.venv\Scripts\python.exe .\run_station_batch.py `
  --config .\configs\experiments\fof2_fast_ml_24h_automl_shap.json `
  --station-file .\configs\station_sets\fof2_fast_ml_24h_all_available.txt

# После фильтрации, без AutoML
.\.venv\Scripts\python.exe .\run_station_batch.py `
  --config .\configs\experiments\fof2_fast_ml_24h_filtered.json `
  --station-file .\configs\station_sets\fof2_fast_ml_24h_all_available.txt

# После фильтрации, с AutoML/SHAP
.\.venv\Scripts\python.exe .\run_station_batch.py `
  --config .\configs\experiments\fof2_fast_ml_24h_filtered_automl_shap.json `
  --station-file .\configs\station_sets\fof2_fast_ml_24h_all_available.txt
```

В `run_ml_baselines.py` отдельно контролируется защита от утечки будущего: последние точки train-окна отсекаются, если их target уже попадает в validation или test. Признаки выбираются заново для каждого окна, потому что покрытие данных меняется от станции к станции и от периода к периоду.

## Результаты анализа

Результаты ML-запусков сохраняются в `artifacts/`. Внутри находятся метрики, прогнозы, подобранные параметры, важность признаков и краткие отчеты по станциям.

Сводные таблицы и графики для анализа лежат в `reports/`. По ним можно смотреть качество моделей, сравнивать станции, оценивать различия по широтным зонам и проверять устойчивость временных рядов.

В проекте уже есть несколько направлений анализа:

- качество прогноза `foF2` по отдельным станциям;
- сравнение моделей между собой;
- сравнение ошибок по широтным зонам;
- анализ стационарности временных ходов `foF2`;
- проверка покрытия и качества исходных рядов.

Для анализа стационарности используется `notebooks/stationarity_latitude_analysis.ipynb`. Он берет ряды из feature-файлов, то есть из тех данных, которые реально участвовали в обучении, и считает ADF/KPSS по станциям и широтным зонам.
